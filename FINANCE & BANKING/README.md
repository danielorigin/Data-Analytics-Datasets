## About the Dataset

This synthetic banking transaction dataset was created to simulate **real-world retail banking transactions** and provide a practical dataset for learning, analysis, visualization, and portfolio development.

The dataset contains transaction-level banking records covering **deposits, withdrawals, transfers, payments, customer activity, risk assessment, fraud indicators, and AML/KYC compliance information**.

It is designed to support practical **Finance & Banking analytics** across transaction behavior, customer segmentation, fraud detection, compliance monitoring, risk analysis, and digital banking adoption.

The dataset is suitable for:

**Excel · SQL · Python/Pandas · Power BI · Tableau · R/RStudio**

---

## Context

Real banking transaction data can be difficult to access because of **privacy, confidentiality, financial regulations, and data protection requirements**.

This dataset was created as a safe synthetic alternative for students, analysts, data professionals, and portfolio developers who want to practice working with realistic financial transaction data.

The dataset simulates transactions from a **German retail banking environment**, including domestic and international transactions across multiple currencies.

## Data Quality

The dataset intentionally contains some realistic data-quality challenges, making it suitable for demonstrating a complete professional analytics workflow.

### Quality Issues

The dataset includes approximately:

* **2–6% missing values** in selected fields such as merchant names and credit scores
* **1.2% duplicate transactions**
* Inconsistent account status formats
* Inconsistent payment method formats
* Mixed capitalization in status fields
* Inconsistent currency code formatting
* Occasional unusual or negative transaction amounts

### Completeness

* Transaction IDs are complete
* Transaction amounts are complete
* Merchant information contains some missing values
* Credit score information contains some missing values

### Consistency

Some categorical fields contain inconsistent formatting, for example:

```text
Active
active
ACTIVE
```

Currency codes may also appear in inconsistent formats:

```text
EUR
eur
```

These issues provide opportunities to practice **standardization, validation, and data cleaning**.

## Important Note

> **This is a fully synthetic dataset created for educational, analytical, and portfolio purposes.**

It does **not** contain real customer accounts, real banking transactions, real financial records, or confidential information from any bank.

Although the dataset simulates a **German retail banking environment**, the records are artificially generated and should not be interpreted as actual data from a German bank or financial institution.

The AML, KYC, fraud, risk, and credit-related fields are included for **analytics and learning purposes only** and should not be used to make real financial, compliance, credit, or customer decisions.
